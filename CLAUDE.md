# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build preferences

### Evidence and Claims
- Every number in a README, contract, or analysis doc must be traceable to a committed artifact or logged run. Never carry numbers from a scratchpad probe into a document.
- Do not state a quantitative claim (window counts, noise floors, arc lengths, runtimes) without measuring it first — measure the file seams, run the check, read the log.
- Frozen evidence (e.g., v0.7.2 outputs) is NEVER recomputed with revised parameters. Flag the conflict instead.
- Committed evidence from earlier builds should be changed with care to avoid regression. Flag instead of changing silently.

### Scope Discipline
- Plan-first: when I ask for a plan, contract, or build-plan section, produce ONLY the document. Do not begin implementing parser/pipeline code until I explicitly approve the plan. Stop and report if you want to expand beyond an approved build list.
- Never expand beyond the agreed scope mid-execution. If you discover an adjacent defect, finish the scoped edits, STOP, and report it as a separate proposal rather than fixing it silently.
- Prefer the smallest change that satisfies the requirement; if a fix balloons (e.g., rewriting a decoder), present option A (minimal) vs option B (full) and wait.

### Documentation Style
- Annotations and inline notes in contracts/build plans are ONE SENTENCE. Avoid multi-paragraph justifications inside doc edits.
- Contract additions are terse; rationale goes in chat, not in the document.
- Whenever possible, aim to use fewer words.

Geometry and mass are **estimates**: box (1.0, 5.0, 1.0) m, `A_ref` **1.0 m²**, mass **419.0 kg** fixed for both satellites and every window. - **The window-4 Swarm A burn, and what caught it.** `moderate_2022_04` Swarm A takes a real **+2218 m** orbit raise at t0 + 4.217 d (implied ΔV +1.25 m/s), which **railed its fitted Cd at the 1.5 floor** — that Cd is an artifact, not a body property, and every Swarm window-4 A row is read that way. Per the **2026-08-21 contract amendment**, a tier-2 CLEAN is **weak evidence, not a quiet window**.
- **`CD_FIT_TOL = 0.002`, and do not loosen it.** The fit returns the midpoint of a bracket narrowed to at most `tol`, so it cannot resolve Cd differences much below `tol`. At a fitted Cd of 2–4 that is 0.05–0.1 %; v0.7.2's `0.02` would be 0.5–1 %, the same size as the twin deviations being measured. ### Validation evidence (what has actually been measured)

Two post-v1 efforts produced propygator's entire external evidence base. **Both rest on a single satellite** — that limitation is what the in-flight study exists to attack.

**Real-world validation study** (2026-07-12 → 07-16, `v0.7.2`; findings `docs/real-world-validation-findings.md`; evidence + `run_all.py` regenerate/`--verify` orchestrator in `experiments/real-world-validation/`). Targets *self-consistent wiring bugs* — the class internal tests structurally cannot see.

- **LAGEOS-2 vs ILRS** — day-1 residual 3.6 m RMS (Checkpoint A → GO); per-toggle ablation matrix all PASS, `planets_third_body` null as claimed.
- **GRACE-FO vs GNV1B** (solar-quiet / solar-max / Gannon-storm windows) — a single fitted Cd collapses along-track residuals to 1.9 / 6.4 m (calm). The fitted-Cd swing **1.98 → 3.32 → 3.97** on A_ram is the measured NRLMSISE-00 density-bias lever. A-priori Cd tables are DSMC-credible, the box adding only *absorbable* scale for ram-dominated bodies → Checkpoint B **deferred** the `box_and_panels` geometry upgrade. Storms defeat a scalar-Cd fit (119 m caveat).
- **Unplanned finding: Orekit's `NRLMSISE00` at default switches is daily-Ap-driven** (proof: `gracefo/probes/probe_ap_driving.py`) — storms smear across the whole UTC day. The ap-history mode `withSwitch(9, -1)` is a named follow-on needing its own study; it is explicitly **out of scope** for the extended-validation branch because it would move every storm-time number in the repo.
- **Fitter vs Space-Track catalog** — converges on measured truth (~630 m post-fit RMS, the §1.2 lossiness class) and predicts at catalog parity (0.83–2.10×) with regime-appropriate `fit_bstar`. The fitting-span sweep **vindicated the shipped 2-day default**. The §1.2 State path is free *iff* the ballistic coefficient is calibrated to single-digit-% — the a-priori tables structurally can't meet that bar, so attitude-dependent spacecraft take the external propagate-then-fit route (the State path has no attitude parameter).
- Guarded by `tests/propagation/test_real_world_{lageos,gracefo}.py`, `tests/tle/test_fitter_real_world.py`, and the shared `tests/propagation/real_world_gnv1b.py` fixture module (fixtures emitted by the drivers' `--emit-fixture` flags). **Tolerance policy: measured × generous margin, relationships over absolutes** — pins prove the wiring didn't regress, not that a number is exact.

**TLE fit strategy experiment** (2026-07-19, shipped in `v0.8.0`; evidence `experiments/tle-fit-strategy/`, recipe `docs/tle-fitting-playbook.md`, open threads `docs/tle-fit-strategy-findings.md`, walkthrough notebook 07 §9). Answers *what a user should DO with the `FitResult` fields*; no contract change.

- **Two-stage self-calibrated B\* transplant** — fit B\* free on ~2 d → hold it via the carrier idiom (`initial_guess` + `fit_bstar=False`) → refit elements on the freshest 1 d. Best catalog-free active-regime config on 3 of 4 anchors.
- **The r/s trust gate**, computable from `FitResult` alone: **r = σ₀·σ(B\*)/|B\*| < 0.05** on the 2 d staging fit; **s = cross-span B\* drift |B\*₃d−B\*₂d|/|B\*₂d| < 0.1**. Classified all 9 anchor-window combinations correctly — quiet r 0.15–1.14 (never certifies), active r 0.020–0.024, storm r 0.011 **but** s 0.323. **r certifies in-arc observability only; s catches nonstationarity** — the storm 3 d fit had the *smallest* r and the *worst* forecast.
- **Quiet's catalog-free default is B\* = 0 + fresh 1 d elements** to ~3 d horizons; calibrated B\* pays only ≥ 4 d.
- **Measured rejects:** the physical-formula B\* (½ρ₀CdA/m — up to 76 km at +4 d), every 1 d free-B\* fit's B\*, and **epoch-at-arc-end fitting** (a < 2 m no-op — validates the §1.2 epoch-at-start rule).
- Fading-memory age-weighting (internals-only, probe 2) is the single-fit rival; its pre-registered §1.2-amendment bar lives in the findings note and is resolved by the in-flight study's **Chunk 18 `[bench-3]`** (the pivot deleted the checkpoints), whose default is **DEFER**.
- **Noise floor:** anchor scatter is 2–3×, so differences < 1.5× are noise. The sweep's "quiet: longer span is better" did **not** replicate across anchors.

### As-built notes worth knowing

Design rationale lives in the archived docs; these are the traps and non-obvious decisions.

**Tier B drag (`BoxFaceCd`)** — a per-face, incidence-resolved free-molecular drag table for a **convex box only** (`solar_array_area_m2 == 0`; misuse fails at *construction*). Orekit-free generator `scripts/generate_box_face_cd_table.py` → `data/box_face_cd_default.npz` (cross-validated ≪ 1% on `CdA`; grid floored at 0.0 since `v0.7.3`). Benefit study → GO **with caveat**: material only for large, flat, edge-on bodies (solar/drag sails, ~2× along-track); negligible for conventional buses.

**ECEF `InPlaneTracking`** — `ecef` re-aims the mode's **primary** axis onto the Earth-relative wind `v_rel = v − ω⊕×r` (the *inverse* of NadirPointing's secondary-slot swap), so a feathered sail holds ~0° angle of attack; +Z becomes best-effort on the orbit normal (off by ≤ ~3.8° in LEO). Default bit-identical; metadata token always `in_plane_tracking:vel=<ref>`. **LEO is the validated domain** — a near-GEO run completes but carries a physically meaningless noise attitude (only *exactly* `v_rel = 0` raises, unreachable in float). `LofOffset`-ecef is the named follow-on; `LofAligned`-ecef is permanently redundant.

**Live-dashboard mutate-in-place** (`tracking/live.py`) — build-once / mutate-in-place at `blit=False`: static curves refreshed via `_draw_static` (never `ax.clear()`), dynamic now-indicators are persistent artists mutated per tick, every axis limit pinned — so toolbar zoom/pan survives every redraw and buffer rebuild (y-limits only *widen* on rebuild, and only while the user hasn't zoomed/panned that panel). **The blit layer proper was declined at Checkpoint A** (1 Hz didn't justify the private-`_blit_cache` coupling). `live_track`'s §1.4 signature and `_TrackerEngine` are unchanged; manual GUI smoke check `run/live_dashboard_demo.py` (gitignored, `--fast`).

**Lumped planetary third body** — `ForceModelConfig.planets_third_body: bool = False`, one lumped toggle wiring `ThirdBodyAttraction` for the seven non-Earth planets off the DE ephemeris already in orekit-data (accessors in `core/bodies.py`; metadata token `third_body:planets`; off in every preset; completeness only, ~1e-10–1e-13 of central gravity).

**`earth_radiation` — parked, and the upstream blocker is now LIFTED (2026-08-03).** Knocke albedo + IR was built then reverted: `KnockeRediffusedForceModel` bounded its crown loop by `asin(R/r)` instead of `acos(R/r)` through Orekit **13.1.5** (~2.4–3× hot at LEO, ~10–20× cold at GEO — the error flips sign with altitude). Fixed upstream in **13.1.6**, and **`orekit_jpype 13.1.7.0` is now available on conda-forge**, so the resume is unblocked. It is **not** authorized on the extended-validation branch — explicitly out of scope, and doubly blocked there because that study freezes the env at `orekit_jpype` 13.1.4.0 while the resume requires the 13.1.6+ upgrade. It is a future `feature/` branch off `main`. Resume kit in `experiments/earth-radiation/`: the parked Chunk-2 runtime as `erp-runtime-chunk2.patch`, the self-verdicting `knocke_bug_probe.py` (**run this first against any new env**), and the recipe. Use a **clone-and-test env, never mutate the working one.** Note the second finding in that README: the model only converges for `angularResolution` ≲ 2°, and the fix changes the LEO cap, so any resolution constant must be re-benchmarked *after* upgrading. The ERP half of `docs/history/general-upgrades-1.md` stays its binding contract.

**Civil time zones + progress reporting** — `live_track(tz: USTimeZone | tzinfo | None = None)` re-expresses **only the readout clock** in a DST-correct US civil zone (display-only, never a `TimeScale`; `None` stays byte-identical UTC; raw `tzinfo` is the non-US escape hatch; **`python-tzdata`** is a conda dep). `propagate_numerical(progress: bool | ProgressCallback = True)` — the **one deliberate post-freeze §1.1 edit** — streams throttled ASCII **stderr** status (start line *before* JVM boot; 10%/TTY vs coarse 25/50/75 off-TTY); `False` silent, a callable gets the 0→1 fraction. 1.5 and 1.2 inherit both from birth (`tz=` on 1.5's formatters; `progress` on both — 1.2 drives indeterminate mode).

**Feature 1.2 TLE fitter as built** (`tle/fitter.py`; binding contract `features.md` §1.2 + its Outcome note; walkthrough `notebooks/07_tle_fitting.ipynb`) — the repo's first *estimation* feature.

- `fit_tle_detailed(reference: State | Trajectory, *, fitting_span=2 d, force_models, spacecraft, initial_guess, max_iterations=100, fit_bstar=True, norad_id, name, progress=True)` is the engine; `fit_tle` is the thin `.tle` wrapper (identical signature, test-pinned). Returns the frozen `FitResult(tle, iterations, evaluations, rms_m, residuals_m, measurement_epochs, covariance, parameter_names, sigma0, velocity_residuals_ms, residuals_ric_m)`. No `converged` flag — failure raises.
- **Mechanism:** fixed-point-refined seed (`FixedPointTleGenerationAlgorithm` over the `from_state_unfitted` template; `TLEConstants.MU`, *not* the nonexistent `Constants.WGS72_EARTH_MU`) at the **reference start**, raw-template fallback on failed generation → `TLEPropagatorBuilder` + `BatchLSEstimator` (Levenberg–Marquardt) over ≤ 300 evenly subsampled TEME PV measurements (σ 1 m / 1 mm/s, `positionScale` 1 m, threshold 1e-3 — probe-tuned placeholders; `max_iterations` bounds iterations *and* evaluations; the `BSTAR` driver selected iff `fit_bstar`). The one new `@JImplements` proxy is the `BatchLSObserver` (single abstract method, no defaults — trap-free), deduped on the iteration counter to feed `iter N | rms …` progress lines.
- **`covariance` / `parameter_names` / `sigma0`** (v0.8.0 Chunk 6) — the estimator's **raw** physical `(JᵀJ)⁻¹`; basis is **Cartesian TEME at the fitted epoch + `BSTAR`**, the only basis Orekit 13.1.x's `TLEPropagatorBuilder` offers (probe-verified). `sigma0` = √(cost²/(m−n)) is the ×-bridge to residual-scaled sigmas; `sigmas` is a derived property, deliberately not stored. Singular extraction after a converged fit → `covariance=None` + `UserWarning` (never reached in probing, even at ~1 revolution). **The honest B\* read is comparative** — the fitted B\* inflates in step with its sigma on weak arcs, so no single-fit ratio discriminates: raw σ(B\*) collapses ~1200× from a ~1-rev arc to the full pinned GNV1B day. An elected correlation-matrix property was **dropped at its chunk-time probe** (corr(B\*, n) ≈ −0.97 on weak *and* strong arcs — structural collinearity, not a pathology flag).
- **`velocity_residuals_ms` / `residuals_ric_m`** (v0.8.0 Chunk 7) — velocity residual norms `(N,)`, and signed position residuals on RIC axes from the observed PV, `(N, 3)` columns [radial, along-track, cross-track], sign observed − estimated; orthonormal, so row norms reproduce `residuals_m` (pinned at machine precision). The read: **periodic = SGP4 representation error, secular along-track = dynamics mismatch.** **RIC-only by decision** — raw TEME residual vectors mix orbit-frequency rotation into every component and stay one `propagate_tle` call away. Along-track dominates the pinned GNV1B day (RIC RMS 116.5 / 594.4 / 162.1 m); the dominance **inverts** on a ~1-rev arc, so that pin is full-day-only.
- **Covariance symmetry is judged against the Cauchy–Schwarz natural scale σᵢσⱼ** — the earlier entrywise-relative check wrongly rejected a real refit whose near-zero off-diagonals carried rounding noise at 1.1e-8 relative (~7.5e-11 of natural scale). Caught by executing notebook 07 end-to-end.
- **Paths.** *State* (EME2000 only): internal `leo_default`/`SpacecraftConfig()`/`high_precision` ~300-sample reference at `progress=False`; a guard-**terminated** reference warns and fits the realized arc (< 2 samples → clean `ValueError`). *Trajectory*: any frame → TEME internally, leading-portion clip, warn-and-ignore `force_models`/`spacecraft`.
- **Field policy:** identity inherits (kwargs win over `initial_guess` over placeholders), physics fitted-or-zeroed, ṅ/n̈ always 0; assembly through Orekit's formatter + `from_strings` re-validation. Non-convergence → `TLEFitError` (a `PropygatorError` *sibling* of `PropagationError`) with iteration count + last RMS — no partial result, no Java trace.
- **The honest numbers** (pinned in `tests/tle/test_fitter.py`, reproduced live by notebook 07): self-fit and Molniya/SDP4 self-fit recover their sources essentially exactly (< 1 m pinned); the 2-day numerical fit lands **~495 m RMS / ~1119 m max** (pinned ≤ 1 km / 1.5 km — the documented lossiness); B\* on beats off (495 vs 541 m) and **the fitted B\* is a fit residual, not the catalog value**; path (b) `from_arrays` < 10 m.

**Feature 1.5 passes as built** (`tracking/passes.py` + `tracking/visibility.py`; contract `features.md` §1.5 + its Outcome note; walkthrough `notebooks/06_pass_prediction.ipynb`) — `find_passes(tle, station, duration, *, start=None, min_elevation_deg=10.0, visible_only=True, standard_magnitude=None, progress=True)` composes `propagate_tle` + the `look_angles_track` kernel + new physics: coarse 30 s scan → grazing-aware bracket → fine 1 s batched grid + sub-sample interpolation → **per-pass** lighting/magnitude only (never an O(window) sweep), window-edge clamping + always-up warn-once. `visibility.py` holds the pure-NumPy conical-umbra `_is_sunlit` (WGS84-sphere Earth, penumbra = lit), the phase law, and `compute_magnitude` (EME2000-only per the §10 frame rule, no eclipse check — reachable at `tracking.visibility`, deliberately **not** top-level). The magnitude table uses the 1000 km / 50%-phase convention via a +1.24 mag offset, direction-verified against Heavens-Above. `export_passes_ics` is deterministic but **not** RFC 5545 line-folded; `plot_sky_chart` recomputes each pass arc through the **unmodified** `_draw_sky_track` seams; `plot_pass_timeline` is Pass-fields-only (no JVM). **`tz=` lives on the formatters, not `find_passes`** (the approved deviation). ## Architecture invariants

These are enforced at module boundaries; violating them is a bug (architecture §4, §10).

- **Orekit types stay internal.** Public APIs accept/return only propygator types (`Epoch`, `Frame`, `State`, `Trajectory`, `TLE`, `Orientation`, …). JPype/Java objects appear only inside implementations. `to_orekit()` methods annotate the Orekit return type under `if TYPE_CHECKING:` (with a runtime `else:` branch) so no runtime Orekit import leaks into the public type surface — see `Epoch.to_orekit` / `State.to_orekit` for the pattern.
- **Lazy JVM, one JVM per process.** Importing `propygator` must NOT start the JVM. It starts on the first Orekit-touching call (via `_ensure_started()`), or via explicit `propygator.init(vmargs=...)`. JPype cannot re-init the JVM, so `init()` with conflicting `vmargs` raises `JVMAlreadyStartedError`. The "safe before init" surface (all `Epoch`/`Frame`/`State`/config construction + validation; everything except `to_orekit()` and the propagate/fetch/track verbs) is asserted by the pure-Python `tests/core/*` suite — keep accidental Orekit imports out of it (import `jpype`/`orekit_jpype`/`pyhelpers` lazily *inside* functions, never at module top).
- **Units:** SI everywhere internally (m, s, rad, kg); human-friendly (km, deg, days) only at the user-facing boundary.
- **Frames are explicit.** Every `State`/`Trajectory` carries a `Frame`; no defaults, no automatic conversion on `State`-returning paths (users call `.to_frame(...)`). Functions returning non-frame-carrying types (`GeodeticPosition`, `Pass`, scalars) may convert internally. v1 frame set: EME2000 (`J2000` is an enum *alias* of the same member), ITRF, TEME.
- **Time:** all internal time is `Epoch` (carries an explicit `TimeScale`; UTC user-facing, TT for dynamics; conversions explicit). Stored as a two-part `(_int_seconds, _frac_seconds)` count of TAI-seconds-since-J2000 (computed via the TT route for exactness; see `core/time.py` module docstring). Naive `datetime`s rejected at the boundary. **UT1 is deferred** (needs EOP data from a running JVM) — it raises `NotImplementedError` everywhere.
- **Paths:** `pathlib.Path` throughout — no string concat, no `os.path.join`.
- **Logging, never prints:** `logger = logging.getLogger(__name__)` per module; top-level `__init__.py` attaches a `NullHandler`. **One sanctioned exception:** the long-running verbs' progress output — implemented once in `core/progress.py` (`_ProgressReporter`), stderr-only, TTY-gated (non-TTY coarsens to 25/50/75 milestones), opt-out via `progress=False`, never stdout, never the root logger; `logger.info` milestones still fire regardless (architecture §Logging).
- **Frozen dataclasses** for the data model, with shape/dtype/finiteness validation in `__post_init__` (`State`, `Epoch`, `KeplerianElements`, `Orientation`, `GroundStation`, …). Array-backed value types (`State`, `Orientation`) defensively copy inputs, set them read-only, and define value-based `__eq__`/`__hash__` (the dataclass-generated `__eq__` raises on ndarray fields). `Trajectory` is intentionally **not** frozen (`eq=False`, caches an `Ephemeris`) but its backing arrays are set read-only and equality is by identity.

## Module structure & dependency rule

Modern `src/` layout: `src/propygator/{core,propagation,tle,tracking,plotting,io}/` (see architecture §5, §7 for the full tree). Top-level `__init__.py` re-exports `init`/`clear_cache`, the types, the exceptions, and the full shipped verb + config surface (Features 1.1–1.5 + `BoxFaceCd`, `USTimeZone`, `ProgressCallback`, `fit_tle` / `fit_tle_detailed` / `FitResult` / `TLEFitError`); `look_angles_track` / `observer_snapshot` / `compute_magnitude` stay reachable via their subpackages (not top-level). The v1 verb surface is complete. Documented import alias is `pgr` (`import propygator as pgr`).

Dependencies flow inward: `tracking/` → `propagation/`/`tle/` → `core/`. `io/` depends only on `core/` (this is why `GroundStation`/`Pass`/`GeodeticPosition` live in `core/observation.py`, not in `io/` or `tracking/`). Exceptions live in `core/exceptions.py` (the innermost layer) so any subpackage can raise/catch them. **Nothing imports `plotting/`** — it's a leaf, so the core stays testable headless.

## Java↔Python boundary notes (orekit_jpype)

- Import `jpype`/`orekit_jpype`/`orekit_jpype.pyhelpers` **lazily inside functions**, never at module top — `pyhelpers` does `from java.io import File` at import time and cannot even be imported before `initVM()`.
- `Vector3D` etc. are Java objects: extract with getters into NumPy (`np.array([v.getX(), v.getY(), v.getZ()])`).
- Cannot subclass Java classes from Python; implement Java interfaces (custom force models, event detectors, the variable-Cd `DragSensitive`) via `@JImplements`/`@JOverride`. Python proxies do **not** inherit Java `default` methods — implement every default the Java caller invokes, and test inside the real Orekit call path. Custom event detectors use `FunctionalDetector` + a 1-method `ToDoubleFunction` proxy + native `StopOnEvent` (not a raw `EventDetector` proxy) to dodge that default-method trap — reuse `_make_radius_stop_detector`.
- IDE autocomplete on `org.orekit.*` is limited (runtime stubs); red underlines that run fine are normal. mypy treats the `org.orekit.*`/`java.*`/`jpype`/`pandas`/`requests` namespaces as untyped (`ignore_missing_imports` in `pyproject.toml`).
