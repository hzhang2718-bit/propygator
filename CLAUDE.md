## Project state

**propygator** is a Python library for orbital simulation and satellite tracking, built on [Orekit](https://www.orekit.org/) via the `orekit_jpype` wrapper. The package is installable, JVM-free on import, and 1085 tests pass. **All five architecture §12 features are shipped** — v1 is feature-complete and fully released; the post-v1 **real-world validation study** shipped as `v0.7.2`, its Chunk 5 follow-on — the `box_face_default` leeward-floor fix — as `v0.7.3` (2026-07-17), and its Chunk 6 follow-on — the `FitResult` covariance / σ₀ exposure — as `v0.8.0` (2026-07-18, the current version; branch `feature/fitresult-covariance`). One maintainer-elected, order-independent follow-on remains open, its own branch off `main` when picked up: **Chunk 7 (`FitResult` residual diagnostics — velocity norms + signed RIC position residuals, elected 2026-07-17)** — blueprint is Chunk 7 of `docs/build-plan-real-world-validation.md`. (Chunk 6's 2026-07-17-elected correlation-matrix property was **dropped at its chunk-time probe** — the corr(B\*, n) read it was elected for measures ≈ −0.97 on weak *and* strong arcs, structural collinearity rather than a pathology flag; the §1.2 amendment records the evidence.)

**Real-world validation study (2026-07-12 → 07-16, shipped as `v0.7.2`; plan `docs/build-plan-real-world-validation.md` — Chunks 0–4 done, Chunk 5 shipped as `v0.7.3`, plan kept active for the remaining follow-ons Chunks 6–7, retiring to `docs/history/` when they close; findings `docs/real-world-validation-findings.md`; evidence + `run_all.py` regenerate/verify orchestrator under `experiments/real-world-validation/`):** the numerical propagator and TLE fitter measured against real orbits for the first time — the study targets *self-consistent wiring bugs*, the class internal tests structurally cannot see. Results: **LAGEOS-2 vs ILRS** day-1 residual 3.6 m RMS (Checkpoint A → GO, tier 1), per-toggle ablation matrix all PASS with `planets_third_body` null as claimed; **GRACE-FO vs GNV1B** (solar-quiet / solar-max / Gannon-storm windows) — a single fitted Cd collapses along-track residuals to 1.9 / 6.4 m (calm), the fitted-Cd swing 1.98→3.32→3.97 on A_ram is the measured NRLMSISE-00 density-bias lever, the a-priori Cd tables are DSMC-credible with the box adding only *absorbable* scale for ram-dominated bodies (Checkpoint B → `box_and_panels` geometry upgrade **deferred**), storms defeat a scalar-Cd fit (119 m caveat), and the one unplanned finding: **Orekit's `NRLMSISE00` at default switches is daily-Ap-driven** (proof: `gracefo/probes/probe_ap_driving.py`; the ap-history mode `withSwitch(9, -1)` is a named follow-on needing its own validation study); **fitter vs Space-Track catalog** — converges on measured truth (~630 m post-fit RMS, the §1.2 lossiness class) and predicts at catalog parity (0.83–2.10×) with regime-appropriate `fit_bstar` (fit B\* when drag is observable, hold it when quiet — §1.2's own guidance validated), the fitting-span sweep **vindicated the shipped 2-day default**, and the §1.2 State path is free *iff* the ballistic coefficient is calibrated to single-digit-% (the a-priori tables structurally can't meet that bar; attitude-dependent spacecraft take the measured-equivalent external propagate-then-fit route — the State path has no attitude parameter). Guarded by three pinned test files (`tests/propagation/test_real_world_{lageos,gracefo}.py`, `tests/tle/test_fitter_real_world.py` + the shared `tests/propagation/real_world_gnv1b.py` fixture module; fixtures emitted by the drivers' `--emit-fixture` flags; tolerance policy: measured × generous margin, relationships over absolutes) and the README "Validation" section.

The five `v0.5.0` upgrades (binding designs in `docs/history/general-upgrades-1.md`; build plans archived under `docs/history/`, Supercessions folded back into `features.md`/`architecture.md`):

**Tier B drag (`BoxFaceCd`)** — a per-face, incidence-resolved free-molecular drag table for a **convex box only** (`solar_array_area_m2 == 0`; misuse fails at *construction*). The Orekit-free generator `scripts/generate_box_face_cd_table.py` → `data/box_face_cd_default.npz` (cross-validated ≪ 1% on `CdA`; since `v0.7.3` the grid is floored at 0.0 — see the generator docstring's "Leeward floor"), the pure-Python `BoxFaceCd` type in `spacecraft.py` (re-exported beside `VariableCd`), and the per-face path in the shared `DragSensitive` proxy. Benefit study → GO with caveat: material only for large, flat, edge-on bodies (solar/drag sails, ~2× along-track); negligible for conventional buses.

**ECEF `InPlaneTracking`** — `velocity_reference: "inertial" | "ecef"`; `ecef` re-aims the mode's **primary** axis onto the Earth-relative wind `v_rel = v − ω⊕×r` (reusing the shipped ECEF `TargetProvider`, the *inverse* of NadirPointing's secondary-slot swap), so a feathered sail holds ~0° angle of attack; +Z becomes best-effort on the orbit normal (off by ≤ ~3.8° in LEO). Default bit-identical; metadata token always `in_plane_tracking:vel=<ref>`. **LEO is the validated domain** — a near-GEO run completes but carries a physically meaningless noise attitude (only *exactly* `v_rel = 0` raises, unreachable in float). `LofOffset`-ecef is the named follow-on; `LofAligned`-ecef is permanently redundant.

**Live-dashboard mutate-in-place** (`tracking/live.py`) — the display layer went from clear-and-redraw to **build-once / mutate-in-place at `blit=False`**: static curves refreshed via `_draw_static` (never `ax.clear()`), dynamic now-indicators are persistent artists mutated per tick, every axis limit pinned — so toolbar zoom/pan survives every redraw and buffer rebuild (the headline win; y-limits only *widen* on rebuild, and only while the user hasn't zoomed/panned that panel). **The blit layer proper was declined at Checkpoint A** (1 Hz didn't justify the private-`_blit_cache` coupling — a named later optimization). `live_track`'s §1.4 signature and `_TrackerEngine` are unchanged; manual GUI smoke check `run/live_dashboard_demo.py` (gitignored, `--fast`).

**Lumped planetary third body** — `ForceModelConfig.planets_third_body: bool = False`, **one lumped toggle** wiring `ThirdBodyAttraction` for the seven non-Earth planets off the DE ephemeris already in orekit-data (accessors in `core/bodies.py`; metadata token `third_body:planets`; off in every preset; completeness only, ~1e-10–1e-13 of central gravity). **Its companion `earth_radiation` (Knocke albedo + IR) was built then reverted — blocked on a horizon-cap bug (`asin(R/r)` vs `acos(R/r)`) in `KnockeRediffusedForceModel` in every installable Orekit ≤ 13.1.5 (~2.4–3× hot at LEO, ~10–20× cold at GEO; fixed upstream in 13.1.6, but no `orekit_jpype` wrapper ≥ 13.1.6 exists yet).** Resume kit — parked patch + self-verdicting probe + recipe — in `experiments/earth-radiation/` (clone-and-test env, never mutate the working one; the ERP half of `general-upgrades-1.md` stays its binding contract).

**Civil time zones + progress reporting** — **Part A:** `live_track(tz: USTimeZone | tzinfo | None = None)` re-expresses **only the readout clock** in a DST-correct US civil zone via the `USTimeZone` enum + `_resolve_tz` in `core/time.py` (display-only, never a `TimeScale`; `None` stays byte-identical UTC; raw `tzinfo` is the non-US escape hatch; **`python-tzdata`** is now a conda dep). **Part B:** `propagate_numerical(progress: bool | ProgressCallback = True)` — the **one deliberate post-freeze §1.1 edit** — streams throttled ASCII **stderr** status via `core/progress.py`'s `_ProgressReporter` (start line **before** JVM boot; 10%/TTY vs coarse 25/50/75 off-TTY; honest final line on **every** exit path via one wide `try/finally`); `False` silent, a callable gets the 0→1 fraction (`ProgressCallback`, top-level). 1.5 and 1.2 inherit both from birth (`tz=` on 1.5's formatters; `progress` on both — 1.2 drives the reporter's indeterminate mode).

**Feature 1.2 TLE fitter as built** (`tle/fitter.py`; binding contract `features.md` §1.2 with its as-built Outcome note — the repo's first *estimation* feature; walkthrough in `notebooks/07_tle_fitting.ipynb`). The committed feasibility probe (`experiments/tle-fitting/`) converged **all 19 fits** and pre-tuned the estimator constants; its Checkpoint-A amendments pulled **`fit_tle_detailed` + `FitResult`** in-contract (diagnostics are free from the estimator; no `converged` flag — failure raises) and pinned the seed to the **fixed-point refinement** (`FixedPointTleGenerationAlgorithm` over the `from_state_unfitted` template; `TLEConstants.MU`, not the nonexistent `Constants.WGS72_EARTH_MU`). `fit_tle_detailed(reference: State | Trajectory, *, fitting_span=2 d, force_models, spacecraft, initial_guess, max_iterations=100, fit_bstar=True, norad_id, name, progress=True)` is the engine returning the frozen `FitResult(tle, iterations, evaluations, rms_m, residuals_m, measurement_epochs, covariance, parameter_names, sigma0)` — the last three the `v0.8.0` covariance amendment (raw physical covariance in the Cartesian-TEME-at-epoch + `BSTAR` basis, `None` + warning iff extraction is singular; σ₀ the ×-bridge to residual-scaled sigmas; `sigmas` a derived property, deliberately not stored) — and `fit_tle` is the thin `.tle` wrapper (identical signature, test-pinned). Mechanism: the fixed-point-refined seed at the **reference start** (raw-template fallback on a failed generation) → `TLEPropagatorBuilder` + `BatchLSEstimator` (Levenberg–Marquardt) over ≤ 300 evenly subsampled TEME PV measurements (σ 1 m / 1 mm/s, `positionScale` 1 m, threshold 1e-3 — probe-tuned placeholders; `max_iterations` bounds iterations *and* evaluations; the `BSTAR` driver selected iff `fit_bstar`); the one new `@JImplements` proxy is the `BatchLSObserver` (single abstract method, no defaults — trap-free), deduped on the iteration counter to feed `iter N | rms …` indeterminate-mode progress lines (callable form gets the iteration-budget fraction; wide `try/finally` honest final line). **State path** (EME2000 only): internal `leo_default`/`SpacecraftConfig()`/`high_precision` ~300-sample reference at `progress=False`; a guard-**terminated** reference warns and fits the realized arc (< 2 samples → clean `ValueError`). **Trajectory path**: any frame → TEME internally, leading-portion clip, warn-and-ignore `force_models`/`spacecraft`. Field policy: identity inherits (kwargs win over `initial_guess` over placeholders), physics fitted-or-zeroed, ṅ/n̈ always 0; assembly through Orekit's formatter + `from_strings` re-validation. Non-convergence → `TLEFitError` (a `PropygatorError` *sibling* of `PropagationError`, `core/exceptions.py`) with iteration count + last RMS, no partial result, no Java trace. **The honest numbers** (pinned in `tests/tle/test_fitter.py`, reproduced live by notebook 07): self-fit and Molniya/SDP4 self-fit recover their sources essentially exactly (< 1 m pinned); the 2-day numerical fit lands **~495 m RMS / ~1119 m max** (pinned ≤ 1 km / 1.5 km — the documented lossiness); B\* on beats off (495 vs 541 m) and the fitted B\* is a fit residual, not the catalog value; path (b) `from_arrays` < 10 m.

**Feature 1.5 passes as built** (`tracking/passes.py` + `tracking/visibility.py`; binding contract `features.md` §1.5 with its as-built Outcome note): `find_passes(tle, station, duration, *, start=None, min_elevation_deg=10.0, visible_only=True, standard_magnitude=None, progress=True)` composes `propagate_tle` + the `look_angles_track` kernel + the new physics: coarse 30 s scan → grazing-aware bracket → fine 1 s batched grid + sub-sample interpolation → per-pass lighting/magnitude only (never an O(window) sweep), window-edge clamping + always-up warn-once, determinate progress. `tracking/visibility.py` holds that new physics: pure-NumPy conical-umbra `_is_sunlit` (WGS84-sphere Earth, penumbra = lit), the phase law, and `compute_magnitude` (EME2000-only per the §10 frame rule, no eclipse check — reachable at `tracking.visibility`, deliberately **not** top-level). `Pass` gained three `None`-default azimuth fields; `core/catalogs.py` gained the cited McCants-`qsmag` standard-magnitude table (→ the 1000 km / 50%-phase convention via the +1.24 mag offset, direction-verified against Heavens-Above). Consumers, all top-level: `passes_to_dataframe` (tz-aware datetimes), `export_passes_csv` (UTC + metadata header), `export_passes_ics` (hand-rolled VCALENDAR, deterministic output, **not** RFC 5545 line-folded), `plot_sky_chart` (recomputes each pass arc, lit/eclipse segments through the **unmodified** `_draw_sky_track` seams), `plot_pass_timeline` (Pass-fields-only, no JVM). `tz=` lives on the formatters, not `find_passes` (the approved deviation). Scan/plot constants are tunable placeholders in `tracking/passes.py` / `plotting/passes.py`. Skyfield cross-check fixture at `experiments/pass-verification/` (throwaway venv per `docs/experiments_venv.md`; 10-pass ISS/Durham table pinned into `test_passes.py`, agreement < 2 s / < 1° / < 0.1°); as-built deltas in the `features.md` §1.5 Outcome note; walkthrough in `notebooks/06_pass_prediction.ipynb`.

### Where things live

All shipped code is on `main`; the full public surface is re-exported from the top-level `__init__.py`, which stays JVM-free.

- **`_orekit_init.py`** — lazy-JVM init: `init()`, `clear_cache()`, orekit-data resolution, `_ensure_started()`.
- **`core/`** — the pure-Python data model (`Epoch`/`TimeScale`, `Frame`, `State`, `Trajectory`, `KeplerianElements`, `Orientation`, `GroundStation`/`GeodeticPosition`/`Pass`, `AzElRange`, `TLE`, exceptions), all constructible + validating with no JVM (the "safe before init" surface). Plus the Orekit-crossing conversion layer (`to_orekit`/`to_frame`/`to_keplerian`/`Trajectory.at`/`to_geodetic`; `Epoch.to_orekit` is the reference lazy-bootstrap pattern), `bodies.py` (WGS84 Earth (ITRF) + Sun/Moon/seven-planet accessors behind `_ensure_started()`), `sampling.py` (shared output grid), `catalogs.py` (name→NORAD + the cited standard-magnitude table), the `TLE` type in `tle.py` (parse/checksum/`from_norad_id`/`from_state_unfitted`), the sky-view kernel in `observation.py` (`look_angles`/`sun_look_angles`/`moon_look_angles`/`look_angles_track`/`observer_snapshot`), the civil-display `USTimeZone` enum + `_resolve_tz` in `time.py` (v0.5.0; display-only, never a `TimeScale`), and `progress.py` (v0.5.0) — `_ProgressReporter` (determinate + indeterminate modes, TTY gate, 10%/heartbeat throttle, idempotent `close()`) + the public `ProgressCallback` alias behind every long-running verb's `progress=`.
- **`propagation/`** — `propagate_numerical` (`numerical.py`) + frozen config dataclasses (`ForceModelConfig`, `IntegratorConfig`, `SpacecraftConfig`/`SpacecraftGeometry`/`VariableCd`/`BoxFaceCd`) + the 7-mode attitude family (`LofAligned`/`LofOffset`/`Inertial`/`SunPointing`/`NadirPointing`/`InPlaneTracking`/`CustomAttitude`; `NadirPointing` **and** `InPlaneTracking` take `velocity_reference="inertial"|"ecef"` — one shared custom `TargetProvider`, `attitude._build_ecef_velocity_target_provider`, in the *secondary* slot for nadir and the *primary* slot for in-plane) + the altitude/regime **guard system** (`guards.py`). Guards: terminal radius event detectors for impact (`r=R⊕`) / escape (`r≈327,000 km`); `AltitudeLimits` (the `limits=` keyword, tightest-of nesting); the min-step re-entry catch with partial-trajectory recovery; the two-tier drag-regime warn-once (Kn floor + table edges — the Kn floor scanned at runtime from a conservative composition embedded in `guards.py`, since Orekit exposes only total density and pymsis is not a runtime dep); and stop-and-report assembling a partial `Trajectory` via the additive `terminated`/`termination_reason`/`termination_epoch` metadata keys. - **`tle/`** — `propagate_tle` (`propagator.py`); `fetch_tle` + 6h/24h on-disk cache (`sources.py`, CelesTrak-only; transport failures wrapped as `TLEFetchError`). ## Architecture invariants

These are enforced at module boundaries; violating them is a bug (architecture §4, §10).

- **Orekit types stay internal.** Public APIs accept/return only propygator types (`Epoch`, `Frame`, `State`, `Trajectory`, `TLE`, `Orientation`, …). JPype/Java objects appear only inside implementations. `to_orekit()` methods annotate the Orekit return type under `if TYPE_CHECKING:` (with a runtime `else:` branch) so no runtime Orekit import leaks into the public type surface — see `Epoch.to_orekit` / `State.to_orekit` for the pattern.
- **Lazy JVM, one JVM per process.** Importing `propygator` must NOT start the JVM. It starts on the first Orekit-touching call (via `_ensure_started()`), or via explicit `propygator.init(vmargs=...)`. JPype cannot re-init the JVM, so `init()` with conflicting `vmargs` raises `JVMAlreadyStartedError`. The "safe before init" surface (all `Epoch`/`Frame`/`State`/config construction + validation; everything except `to_orekit()` and the propagate/fetch/track verbs) is asserted by the pure-Python `tests/core/*` suite — keep accidental Orekit imports out of it (import `jpype`/`orekit_jpype`/`pyhelpers` lazily *inside* functions, never at module top).
- **Units:** SI everywhere internally (m, s, rad, kg); human-friendly (km, deg, days) only at the user-facing boundary.
- **Frames are explicit.** Every `State`/`Trajectory` carries a `Frame`; no defaults, no automatic conversion on `State`-returning paths (users call `.to_frame(...)`). Functions returning non-frame-carrying types (`GeodeticPosition`, `Pass`, scalars) may convert internally. v1 frame set: EME2000 (`J2000` is an enum *alias* of the same member), ITRF, TEME.
- **Time:** all internal time is `Epoch` (carries an explicit `TimeScale`; UTC user-facing, TT for dynamics; conversions explicit). Stored as a two-part `(_int_seconds, _frac_seconds)` count of TAI-seconds-since-J2000 (computed via the TT route for exactness; see `core/time.py` module docstring). Naive `datetime`s rejected at the boundary. **UT1 is deferred** (needs EOP data from a running JVM) — it raises `NotImplementedError` everywhere.
- **Paths:** `pathlib.Path` throughout — no string concat, no `os.path.join`.
- **Logging, never prints:** `logger = logging.getLogger(__name__)` per module; top-level `__init__.py` attaches a `NullHandler`. **One sanctioned exception (v0.5.0):** the long-running verbs' progress output — implemented once in `core/progress.py` (`_ProgressReporter`), stderr-only, TTY-gated (non-TTY coarsens to 25/50/75 milestones), opt-out via `progress=False`, never stdout, never the root logger; `logger.info` milestones still fire regardless (architecture §Logging).
- **Frozen dataclasses** for the data model, with shape/dtype/finiteness validation in `__post_init__` (`State`, `Epoch`, `KeplerianElements`, `Orientation`, `GroundStation`, …). Array-backed value types (`State`, `Orientation`) defensively copy inputs, set them read-only, and define value-based `__eq__`/`__hash__` (the dataclass-generated `__eq__` raises on ndarray fields). `Trajectory` is intentionally **not** frozen (`eq=False`, caches an `Ephemeris`) but its backing arrays are set read-only and equality is by identity.

## Module structure & dependency rule

Modern `src/` layout: `src/propygator/{core,propagation,tle,tracking,plotting,io}/` (see architecture §5, §7 for the full tree). Top-level `__init__.py` re-exports `init`/`clear_cache`, the types, the exceptions, and the full shipped verb + config surface (Features 1.1/1.2/1.3/1.4/1.5 + `BoxFaceCd`, `USTimeZone`, `ProgressCallback`; 1.2 adds `fit_tle` / `fit_tle_detailed` / `FitResult` / `TLEFitError`) — see "Where things live" for the inventory; `look_angles_track` / `observer_snapshot` / `compute_magnitude` stay reachable via their subpackages (not top-level). The v1 verb surface is complete. Documented import alias is `pgr` (`import propygator as pgr`).

Dependencies flow inward: `tracking/` → `propagation/`/`tle/` → `core/`. `io/` depends only on `core/` (this is why `GroundStation`/`Pass`/`GeodeticPosition` live in `core/observation.py`, not in `io/` or `tracking/`). Exceptions live in `core/exceptions.py` (the innermost layer) so any subpackage can raise/catch them. **Nothing imports `plotting/`** — it's a leaf, so the core stays testable headless.

## Java↔Python boundary notes (orekit_jpype)

- Import `jpype`/`orekit_jpype`/`orekit_jpype.pyhelpers` **lazily inside functions**, never at module top — `pyhelpers` does `from java.io import File` at import time and cannot even be imported before `initVM()`.
- `Vector3D` etc. are Java objects: extract with getters into NumPy (`np.array([v.getX(), v.getY(), v.getZ()])`).
- Cannot subclass Java classes from Python; implement Java interfaces (custom force models, event detectors, the variable-Cd `DragSensitive`) via `@JImplements`/`@JOverride`. Python proxies do **not** inherit Java `default` methods — implement every default the Java caller invokes, and test inside the real Orekit call path. Custom event detectors use `FunctionalDetector` + a 1-method `ToDoubleFunction` proxy + native `StopOnEvent` (not a raw `EventDetector` proxy) to dodge that default-method trap — reuse `_make_radius_stop_detector`.
- IDE autocomplete on `org.orekit.*` is limited (runtime stubs); red underlines that run fine are normal. mypy treats the `org.orekit.*`/`java.*`/`jpype`/`pandas`/`requests` namespaces as untyped (`ignore_missing_imports` in `pyproject.toml`).
- Don't `conda update` blindly — the pinned trio (Python 3.11 / OpenJDK 17 / orekit_jpype 13.1.x) is a tested combination; upgrade Orekit by creating a fresh env.
