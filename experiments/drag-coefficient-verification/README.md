# Drag-coefficient verification (reference only)

Empirical check of the load-bearing assumption behind propygator's variable drag
coefficient: that a spacecraft's free-molecular **C_D collapses onto a single
`(altitude, total density)` surface**, independent of the epoch / space-weather
state that produced that density. If that holds, a `(geocentric radius, density)`
lookup table is a sufficient statistic for C_D and never goes stale — which is
exactly the design described in `docs/features.md` §1.1 and generated by
`docs/build-plan-feature-1.1.md` Chunk 5.

> [!IMPORTANT]
> **Status: reference only — not part of the package.** This is an exploratory
> reconstruction, not shipped propygator code and not the Chunk 5 deliverable
> (`scripts/generate_sphere_cd_table.py`). It is **not** imported by propygator,
> **not** run in CI, and **not** linted/type-checked. The C_D model here is a
> stand-in and will **not** be incorporated into the package (not even by copying
> lines over). It is kept as the evidence behind the design decision.

## What it tests

| Tier | Geometry | Question | Result |
|------|----------|----------|--------|
| A | sphere | Does C_D collapse onto one `(alt, ρ)` surface across genuinely different epochs (season, local solar time, latitude, F10.7, Ap)? | **Yes** — scatter at matched `(alt, ρ)` ≈ **0.34 % RMS** |
| B | box / plate | Does it still collapse **at fixed attitude**, for a cube and a thin plate from head-on to grazing? | **Yes** — ≤ ~1.3 % RMS even for an 80° grazing plate |

Both are an order of magnitude under the 15–30 % thermospheric density-model
uncertainty that dominates total drag error, so keying C_D on `(radius, density)`
is sound.

## Files

| File | Role |
|------|------|
| `cd_core.py` | Sphere C_D: Sentman/DRIA closed form, per-species mass-flux weighting over NRLMSISE-00, SESAM-style Langmuir accommodation keyed on atomic-O coverage. Shared by both experiments. |
| `cd_sphere_experiment.py` | Tier A. Sweeps epochs × altitudes and tests the `(alt, ρ)` collapse two ways (assumption-free scatter + a train/test interpolant). Writes `cd_time_independence.png`. |
| `cd_box.py` | Tier B per-face flat-plate C_D (Schaaf–Chambre / Sentman). Self-check: integrating panels over a sphere reproduces `cd_core` to < 0.1 %. |
| `cd_box_experiment.py` | Tier B. The same collapse test at fixed attitude, for a cube and a plate. Writes `cd_tierB.png`. |
| `cd_time_independence.png`, `cd_tierB.png` | Result figures from the authoring run (see Provenance). |
| `cd_sphere_results.txt`, `cd_box_results.txt` | Captured stdout from the authoring run — a point-in-time snapshot of the exact numbers behind the figures and "Results" above. Regenerable via step 4; used by no code. |

## How to run

The dependencies (`scipy`, `pymsis`) are intentionally **not** in the propygator
conda env — that env is a pinned, tested combination. Use a throwaway virtual
environment instead. From **this directory** (PowerShell):

```powershell
# 1. create an isolated environment (any Python 3.10–3.13 works)
python -m venv .venv-experiments

# 2. activate it (the prompt gains a "(.venv-experiments)" prefix)
.\.venv-experiments\Scripts\Activate.ps1

# 3. install the deps (prebuilt wheels — no compiler needed)
pip install -r requirements.txt

# 4. run from THIS directory (the imports are flat, not a package)
python cd_sphere_experiment.py > cd_sphere_results.txt
python cd_box_experiment.py    > cd_box_results.txt

# 5. leave the environment when done
deactivate
```

The `> ...results.txt` redirect captures the full numeric output (the figures only
show summaries). Delete the `.venv-experiments/` folder to remove the environment
entirely; it is gitignored.

If `Activate.ps1` is blocked by PowerShell's execution policy, allow it for the
current session only: `Set-ExecutionPolicy -Scope Process RemoteSigned`.

## Results (local venv run, 2026-06-11)

Exact stdout from the run that produced the committed figures (regenerate any time
with the `> ...results.txt` redirect in step 4):

**Tier A — sphere** (605 points: 55 epochs × 11 altitudes, 300–800 km):

- *Assumption-free scatter* about the per-altitude C_D(ρ) curve: **RMS 0.339 %**,
  95th pct 0.71 %, worst 1.93 % (per-altitude RMS runs 0.16 % at 500–550 km up to
  0.57 % at 800 km).
- *Operational* — table built on 27 epochs, applied to the 28 held-out epochs:
  residual **mean +0.022 %, RMS 0.589 %**, 95th |·| 1.28 %, max |·| 3.16 % (n = 295).

**Tier B — box / plate**, thickness (RMS % scatter at matched `(alt, ρ)`, at fixed
attitude):

| attitude | mean C_D | thickness RMS % |
|----------|---------:|----------------:|
| cube head-on (0°) | 3.536 | 0.714 |
| cube edge-on (45°) | 4.196 | 0.446 |
| cube corner-on | 4.660 | 0.288 |
| plate face-on (0°) | 3.175 | 0.407 |
| plate 60° | 1.301 | 0.269 |
| plate 80° grazing | 0.403 | 1.301 |

Sphere baseline is 0.34 %; even the 80° grazing plate stays at ~1.3 %.

## Provenance

The C_D model here was reconstructed in a Claude analysis sandbox (~2026-06-11). The
committed figures and the numbers in "Results" above were then **regenerated locally**
under the experiment venv on 2026-06-11 — fixed RNG seeds plus deterministic
NRLMSISE-00 make the run reproducible (given the same `pymsis`). The scripts are
**not** executed in the propygator conda env (they need `scipy` / `pymsis`, which it
does not carry). The work originally lived in a single flat directory; it was
reorganized here with the two tiers sharing `cd_core.py`.

## Caveats (what this does and does not establish)

- **Model-based, not flight-data.** It shows that a physically reasonable
  free-molecular C_D model collapses onto `(alt, ρ)`; it presumes that model.
  Appropriate for de-risking a design choice, not a claim of absolute C_D truth.
- **Single-anchor accommodation calibration** (α ≈ 0.90 at 400 km / solar max — a
  commonly-accepted value: Pilinski et al. 2010 SESAM ~0.85–0.93, Moe & Moe 2005 /
  CHAMP ~0.86–0.89; reconciled with the table generator per the drag-validity
  addendum §5, replacing the earlier 0.82). The *collapse* conclusion is a property
  of the mechanism — α tracks atomic-O coverage, which tracks the same heating that
  sets density — not of the calibration constant. *(The committed `*_results.txt`
  were produced at the earlier 0.82 and are regenerated when the addendum's expanded
  experiment is re-run.)*
- **Axis approximation.** The experiment keys on *geodetic altitude* (the pymsis
  input); the shipped design keys on *geocentric radius*. Varying latitude bundles
  some of that spread in, so this is supportive but does not isolate the exact axis.
- **Coverage.** 300–800 km only; the proposed `sphere_default` grid spans
  ~150–1200 km. The fast-changing low end and the high end are not exercised here.
